## 1. プロジェクト概要

### 1.1 ミッション

Threads の自動投稿でフォロワーを獲得し、note 有料記事へ誘導して収益化する。
月間作業時間 90 分以内で、半自動的に収益を生むシステムを構築する。

### 1.2 前提環境

| 項目 | 内容 |
|------|------|
| メインアカウント | goro.money.business@gmail.com |
| 開発環境 | GitHub Codespaces（ターミナル操作） |
| コード管理 | git push（Codespaces → GitHub） |
| AI（本文生成） | Claude（課金済み・チャットUI使用） |
| AI（投稿文生成・バックアップ） | Groq API（無料） |
| リサーチ | Genspark（無料期間） |
| 自動投稿 | GitHub Actions + Python + Threads API |
| データ管理 | Google Sheets（gspread） |
| 収益化 | note 有料記事・月額マガジン |
| リポジトリ | goroyattemiyo/threads-note-autopilot（Private） |

### 1.3 使わないもの

Anthropic API（課金チャットで代替）、Make/Zapier 等の SaaS 自動化ツール、
GAS（GitHub Actions に移植済み）。

### 1.4 収益シミュレーション（1ジャンル・暮らし系）

| 月 | フォロワー | note記事数 | ベスト | リアル | ワースト |
|----|-----------|-----------|--------|--------|----------|
| 1 | 300 | 2本 | 5,000円 | 1,500円 | 0円 |
| 3 | 2,000 | 6本 | 25,000円 | 8,000円 | 2,000円 |
| 6 | 8,000 | 12本+マガジン | 80,000円 | 30,000円 | 8,000円 |
| 12 | 25,000 | 24本+マガジン+ツール | 200,000円 | 70,000円 | 15,000円 |

### 1.5 損益分岐点

月間コスト: GitHub Actions 無料、Sheets 無料、Threads API 無料、
Claude 課金は既存コスト（追加なし）。追加コスト実質 0円。
note 手数料を考慮すると、月 2,250円 以上の売上で黒字。

### 1.6 撤退基準

3 ヶ月運用してフォロワー 500 未満かつ note 売上 0円 の場合、
ジャンル変更またはプロジェクト中止を判断する。

## 2. システムアーキテクチャ

### 2.1 全体フロー

手動：週1回 約30-40分
  Genspark（ネタ収集）
    → Claude チャット（投稿文14本 + note記事生成）
      → Google Sheets「投稿キュー」に貼り付け

自動：GitHub Actions cron 1日2回
  GitHub Actions
    → src/post.py（Sheets から当日投稿を取得）
      → src/threads_api.py（Threads API で投稿）
        → src/sheets.py（投稿済みフラグ・ログ記録）

手動：月2回 約20分
  Claude チャット（note 記事生成）
    → note に公開（最終チェック10分）

自動：週1回
  GitHub Actions
    → src/insights.py（エンゲージメント取得）
      → Sheets「インサイト」に記録

### 3.3 ジャンル追加手順（所要時間 約10分）

  1. cp -r prompts/_template prompts/<genre>
  2. 各 .md ファイルをジャンル固有の文言に書き換え
  3. cp config/_template.yml config/active.yml → ジャンル情報を記入
  4. Google Sheets をテンプレートからコピー
  5. Instagram アカウント作成 → Threads アカウント自動生成
  6. Meta Developer でテストユーザー追加 → アクセストークン取得
  7. GitHub Secrets に PREFIX_ACCESS_TOKEN と PREFIX_USER_ID を追加
  8. git add . && git commit -m "feat: add <genre>" && git push origin main

### 3.4 クロスジャンル戦略

ジャンルが2つ以上になった時点で、クロスコンテンツを企画する。
例: 暮らし × 育児 = 「子育てママの100均ハック」
config の cross_genre セクションで定義し、月1-2回のクロス投稿を実施。

## 4. 投稿戦略

### 4.1 2026年 Threads 環境認識

DAU 1億4,150万人（X の1億2,500万人を超過）。MAU 4億人超。
2026年1月26日に広告が全広告主に開放、オーガニックリーチ低下傾向。
Dear Algo 機能（2026年2月11日）でユーザーがフィード制御可能に。
Topic Tags 本格稼働中。Fediverse（ActivityPub）連携で Mastodon 等にも配信可能。
エンゲージメント率中央値 6.25%（X の 3.6% の約1.7倍）。

### 4.2 投稿比率

自動投稿 93%（週13本）+ 手動交流 7%（週1本の引用リプ + 全リプ返信）

### 4.3 週間コンテンツミックス（Growth Phase: 週14本）

| 種別 | 本数/週 | 内容例 |
|------|---------|--------|
| 商品紹介 | 4 | 「ダイソーの○○が神すぎた」 |
| 比較 | 2 | 「ダイソー vs セリア、○○対決」 |
| 失敗談 | 2 | 「買って後悔した100均ワースト3」 |
| アンケート | 2 | 「キッチン収納、どっち派？」 |
| 豆知識 | 2 | 「○○の意外な使い方」 |
| note 誘導 | 2 | 「詳しくはnoteにまとめました」 |

### 4.4 投稿テキスト仕様

文字数: 200-300文字。
構成: フック（1行目で止める）→ 本文 → CTA。
ハッシュタグ: 2-3個（Topic Tags 併用）。
絵文字: 3個以内。リンク: note CTA 投稿のみ URL 記載。

### 4.5 CTA パターン（A/Bテスト用）

A: 「詳しくはプロフのリンクから」（標準）
B: 「この続き、noteにまとめました」（好奇心型）
C: 「いいね100超えたらnoteで全公開します」（条件型）
D: 「今週末まで490円 → 来週から980円」（緊急型）
E: 「リプで『ほしい』と送ってくれた方にDMします」（エンゲージ型）

### 4.6 Topic Tags 運用

各投稿に1-2個の Topic Tags を付与。ジャンルごとに主要タグを定義。
暮らし系: #100均 #収納 #暮らしのアイデア #ダイソー #セリア #無印良品

### 4.7 Dear Algo 対策

月2回、教育投稿を実施:
「Dear Algo、100均の便利グッズとか収納ハックの投稿をもっと見せてください」
→ フォロワーにも同様の投稿を促し、アルゴリズム上の露出を維持。

### 4.8 Fediverse 連携

Threads アカウント設定で Fediverse 共有を ON にする。
注意: Fediverse に一度共有された投稿は、Threads で削除しても
他サーバーから削除できない。誤投稿のリスクを考慮し、
自動投稿が安定してから有効化する（Phase 2 以降）。

### 4.9 手動交流ルール（週60分）

全リプライに返信（最優先）。
リスト内インフルエンサーの投稿に価値ある引用リプ（1日3件）。
同ジャンルアカウントへのいいね・リプ（1日5件）。
購買意向リプ（「どこで買える？」「欲しい！」等）は即返信 + note 誘導。

## 5. マネタイズ設計

### 5.1 収益4本柱（段階的導入）

| Phase | 期間 | 収益源 | 想定月収（リアル） |
|-------|------|--------|-------------------|
| Phase 1 | 1-3ヶ月目 | 有料記事のみ | 1,500-8,000円 |
| Phase 2 | 4-6ヶ月目 | 有料記事 + AI学習対価還元 | 8,000-20,000円 |
| Phase 3 | 7-9ヶ月目 | 上記 + 月額マガジン | 20,000-40,000円 |
| Phase 4 | 10-12ヶ月目 | 上記 + ツール販売 | 40,000-70,000円 |

### 5.2 各収益源の天井値

有料記事: 月2本 × 490円 × 購入50人 = 49,000円（手数料後 37,000円）
AI学習対価還元: 記事数 × 学習利用度に依存、月 5,000-15,000円
月額マガジン: 980円 × 50人 = 49,000円（手数料後 37,000円）
ツール販売: 3,980-9,800円 × 月10-30本 = 39,800-294,000円

### 5.3 note 記事ポートフォリオ

| 種別 | 頻度 | 価格 | 目的 |
|------|------|------|------|
| 無料記事 | 月4-6本 | 0円 | SEO・信頼構築・AI対価還元 |
| 有料記事（定番シリーズ） | 月2本 | 490-980円 | メイン収益 |
| 有料記事（深掘り特集） | 四半期1本 | 1,480-1,980円 | 高単価 |
| 月額マガジン | 月4配信 | 980円 | 継続収益 |

### 5.4 note AI学習対価還元プログラム

2025年8月開始、参加者1,200人超、総額500万円超の実績。
記事数と学習利用度に応じて対価が支払われるため、
無料記事を月4-6本投稿して対象コンテンツ量を最大化する。
設定: note 管理画面から「AI学習への利用を許可」を ON。

### 5.5 価格戦略

発売直後3日間: 490円（発売記念価格）。
4日目以降: 980円（通常価格）。
レビュー10件超: 1,480円 に値上げ検討。
A/B テスト: 同テーマで 490円版と 980円版を出し、購入率と売上を比較。

### 5.6 ツール販売（Phase 4）

リポジトリのコードは Private のまま。
解説記事・プロンプト集・運用マニュアルを有料 note として販売。
価格帯: 3,980-9,800円。

## 6. データ設計

### 6.1 方針: ハイブリッド方式

ジャンルごとにスプレッドシートを分割 + 集計用横断シートを別途作成。
スキーマバージョンを各シート A1 セルに記載（例: v1.0）。

### 6.2 シート構成（1ジャンルあたり）

シート①「ネタストック」
  A:ID  B:日付  C:商品名  D:ブランド  E:価格
  F:悩み  G:フック案  H:カテゴリ  I:使用済
  例: N001, 2026/03/17, 折りたたみ水切り, ダイソー, 330円,
      狭いキッチン, え、これ330円？, キッチン, FALSE

シート②「投稿キュー」
  A:投稿日  B:時間帯  C:投稿文  D:種別  E:ネタID
  F:投稿済  G:投稿ID  H:エラー
  例: 2026/03/17, morning, （300文字以内）, product_intro,
      N001, FALSE, , 

シート③「投稿ログ」
  A:投稿日時  B:投稿ID  C:投稿文（先頭50文字）
  D:種別  E:ステータス（success/error）

シート④「インサイト」
  A:取得日  B:投稿ID  C:views  D:likes
  E:replies  F:reposts  G:quotes

シート⑤「note実績」
  A:記事タイトル  B:公開日  C:価格  D:累計売上
  E:PV  F:購入数  G:購入率  H:メモ

### 6.3 バックアップ

週次 GitHub Actions で Sheets データを JSON 形式で data/ に保存。
ただし data/ は .gitignore 対象のため、ローカルバックアップとして機能。
重要データの長期保存が必要な場合は、別途 Private Gist 等を検討。

## 7. API・外部サービス仕様

### 7.1 Threads API

| 項目 | 内容 |
|------|------|
| ベースURL | https://graph.threads.net/v1.0/ |
| 認証 | OAuth 2.0 Long-Lived Token |
| トークン有効期限 | 60日 |
| 投稿上限 | 250件/24時間（アプリ単位で共有） |
| テキスト投稿 | POST /{user_id}/threads → POST /{user_id}/threads_publish |
| インサイト | GET /{media_id}/insights |
| 2026年2月追加 | Reply Approvals API（リプ承認管理） |
| 2026年3月追加 | oEmbed トークン不要化 |

### 7.2 Meta Developer 設定

アカウント: goro.money.business@gmail.com
APIアプリ: 1つ（全ジャンル共有）
各ジャンルの Threads アカウントをテストユーザーとして追加。
レート制限: 250件/日は全アカウント共有。
5ジャンル × 2投稿/日 = 10件/日で余裕あり。

### 7.3 トークン管理

| レベル | 方式 | 採用時期 |
|--------|------|----------|
| Lv.1 手動 | 60日ごとに手動リフレッシュ | Phase 1（初期） |
| Lv.2 半自動 | Actions で期限7日前にメール通知 | 2ジャンル目以降 |
| Lv.3 自動 | Actions でリフレッシュ + Secrets 自動更新 | 5ジャンル以上 |

リフレッシュ用エンドポイント:
  GET https://graph.threads.net/refresh_access_token
    ?grant_type=th_refresh_token
    &access_token={long-lived-token}

### 7.4 Google Sheets API

認証: サービスアカウント（JSON キーを GitHub Secrets に保存）。
ライブラリ: gspread + google-auth。
レート制限: 読み取り60回/分、書き込み60回/分。
最適化: バッチ処理（1ジョブあたり読み1回 + 書き1回 = 2 API コール）。

### 7.5 Groq API（バックアップ用・将来実装）

モデル: Llama-3.3-70b-versatile。
用途: 忙しい週の投稿文自動生成。
レート制限: 無料枠で十分。
品質: 星3（Claude の星5には劣る）。

### 7.6 セキュリティルール

認証情報は全て GitHub Secrets に保存。
コード内にトークン・ID をハードコードしない。
ログ出力に認証情報を含めない。
config/active.yml は .gitignore 対象（スプシ ID 等を含むため）。
サービスアカウント JSON は絶対にコミットしない。

| weekly-insights.yml | 毎週日曜 12:00 UTC（JST 21:00） | 約2分 | インサイト収集 |
| monthly-token-check.yml | 毎月1日 00:00 UTC | 約1分 | トークン期限確認 |

### 8.2 月間 Actions 消費量

1ジャンル: (1.5分 × 2回 × 30日) + (2分 × 4回) + 1分 = 99分/月。
無料枠 2,000分に対し、最大20ジャンルまで対応可能。
既存の他リポジトリ分（推定500分）を差し引いても15ジャンルは余裕。

### 8.3 複数ジャンル統合時の最適化

5ジャンル以上になった場合、個別ワークフローから統合ワークフローに切替。
1回の実行で全ジャンルをループ処理し、Actions 消費を約1/5に削減。

### 8.4 リトライ設計

コード内リトライ: 最大3回、指数バックオフ（3秒→6秒→12秒）。
対象: Threads API 一時エラー（5xx）、Sheets API タイムアウト。
対象外: 認証エラー（401）、レート制限（429）。
失敗投稿の扱い: 再投稿せず ERROR フラグを立てる（重複投稿防止）。
ジョブレベル再実行: しない（cron が次の時間帯で別投稿を処理）。

### 8.5 cron のズレ対策

GitHub Actions の cron は最大15分のズレが発生しうる。
投稿時刻の厳密性は不要のため、許容する。
シートの「時間帯」列は morning/evening の区分のみとし、
正確な HH:MM は指定しない。

### 8.6 ログ保持

GitHub Actions のログはデフォルト90日保持。
重要な投稿結果は Sheets の「投稿ログ」に永続記録。

### 9.3 Threads 投稿文生成プロンプト（テンプレート）

  あなたは [[GENRE]] ジャンルの Threads インフルエンサーです。

  ペルソナ: [[PERSONA]]

  生成ルール:
  - 200-300文字以内
  - 1行目はフック（スクロールを止める一言）
  - 本文は具体的な使用シーンと感想
  - 最後にCTA（質問 or note誘導）
  - ハッシュタグ2-3個: [[TOPIC_TAGS]]
  - 絵文字は3個以内
  - 宣伝臭を出さない、友達に話すトーンで

  商品情報:
    商品名: [[PRODUCT_NAME]]
    ブランド: [[BRAND]]
    価格: [[PRICE]]
    解決する悩み: [[PAIN_POINT]]

  投稿種別: [[POST_TYPE]]
  （product_intro / comparison / failure_story / poll / tips / note_cta）

  出力: 投稿文のみを出力。説明や注釈は不要。

### 9.4 note 記事生成プロンプト（テンプレート）

  記事テーマ: [[ARTICLE_THEME]]

  構成:
  1. 導入（300文字）- 読者の悩みに共感、この記事で解決できることを宣言
  2. 本文 - 各アイテムの紹介（写真指示・使用感・評価）
  3. まとめ - ベスト3の再提示、次回予告

  ルール:
  - 無料プレビュー: 全体の30%（導入 + 上位3位まで）
  - 有料パート: 残り70%（2位-1位 + 詳細比較表 + 裏技）
  - 文体: 丁寧だが堅すぎない、実体験ベース
  - 「PR」「広告」が含まれる場合は明記
  - AI生成であることの開示: config設定に従う

  月間データ: [[MONTHLY_TOP_ITEMS]]

  出力: Markdown 形式で記事全文を出力。見出しは ## で統一。

### 9.5 Genspark リサーチ用クエリ（テンプレート）

  週次リサーチ（毎週月曜）:
    "[[BRAND]] [[CURRENT_MONTH]]月 新商品"
    "[[GENRE]] 話題 SNS バズ"

  月次リサーチ（月初）:

    選定基準: インパクト、価格の手頃さ、悩み解決度
    出力形式: JSON配列
    [{"product":"商品名","brand":"ブランド","price":"価格",
      "pain":"悩み","hook":"フック案"}]

### 9.6 プロンプト改善サイクル
